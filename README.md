# Margin Notes

노트에서 글을 선택해 하이라이트하고, 그 하이라이트에 단 코멘트를 **코멘트 1개당 마크다운 파일 1개**로 지정한 폴더에 저장하는 옵시디언 플러그인입니다. 오른쪽 사이드바에서 현재 노트와 보관함 전체의 하이라이트·코멘트를 카드로 모아 봅니다.

- 하이라이트는 노트에 옵시디언 기본 문법 `==텍스트==`로 남습니다. 플러그인을 지워도 그대로 보입니다.
- 코멘트는 노트 밖의 일반 노트라서 검색·태그·백링크·그래프 뷰를 그대로 쓸 수 있습니다.
- 둘은 하이라이트 바로 뒤의 숨김 표시 `%%mn:a1b2c3%%`(앵커 ID)로 이어집니다. 읽기 모드에서는 옵시디언이 숨기고, 라이브 프리뷰에서는 작은 말풍선 아이콘으로 보입니다.

## 설치 (수동)

1. `npm install` 후 `npm run build`로 `main.js`를 만듭니다.
2. 보관함의 `.obsidian/plugins/margin-notes/` 폴더에 `main.js`, `manifest.json`, `styles.css`를 복사합니다.
3. 옵시디언 설정 → 커뮤니티 플러그인에서 **Margin Notes**를 켭니다.

개발할 때는 저장소를 개발 전용 보관함의 `.obsidian/plugins/margin-notes/`에 클론하고 `npm run dev`(감시 빌드)를 켜 두면 됩니다. Hot Reload 플러그인을 쓰면 빌드할 때마다 다시 불러옵니다.

## 사용법

| 하고 싶은 일 | 방법 |
| --- | --- |
| 하이라이트 + 코멘트 | 글을 드래그하면 선택 위에 뜨는 버튼 줄에서 **코멘트**, 또는 우클릭 **하이라이트 + 코멘트** |
| 하이라이트만 | 버튼 줄의 **하이라이트**나 색 점, 스포이드(다른 색 고르기), 또는 우클릭 **하이라이트만** |
| 코멘트 편집 | 사이드바 카드의 코멘트 영역 클릭, 또는 하이라이트에서 우클릭 **코멘트 편집** |
| 본문으로 이동 | 카드의 하이라이트 문구 클릭 (Ctrl/Cmd+클릭 = 새 탭) |
| 카드 찾기 | 본문의 말풍선 아이콘이나 하이라이트 클릭 |
| 색 바꾸기 | 카드 왼쪽 색 띠 클릭 → 팔레트 색 또는 **다른 색 고르기…** |

색은 설정에서 만든 내 팔레트(기본: 노랑·초록·파랑·빨강·보라, 이름은 직접 바꿀 수 있음)에서 고르거나, 컬러 피커로 아무 색이나 고를 수 있습니다. 직접 고른 색은 코멘트 파일에 `mn-color: "#ff8800"`처럼 저장됩니다.

버튼 줄은 하이라이트할 수 있는 선택(한 줄, 코드·기존 하이라이트 밖)에서만 뜨고, 다른 곳을 누르거나 타이핑하거나 스크롤하면 사라집니다. 설정의 **선택하면 버튼 표시**로 끌 수 있습니다.

기본 단축키는 지정하지 않습니다(커뮤니티 심사 기준). **하이라이트 + 코멘트**에 `Ctrl/Cmd+Shift+M`을 직접 지정해 쓰기를 권합니다.

### 명령어

| 명령어 | 동작 |
| --- | --- |
| 선택 영역에 하이라이트 + 코멘트 | 하이라이트하고 코멘트 입력창을 엽니다 |
| 선택 영역에 하이라이트만 | `==문구==`만 넣습니다 |
| 커서 위치 코멘트 편집 | 커서가 있는 하이라이트의 코멘트를 엽니다 |
| 커서 위치 하이라이트 제거 | 하이라이트를 없앱니다. 코멘트 파일 처리는 설정을 따릅니다 |
| 커서 위치를 사이드바에서 보기 | 해당 카드로 스크롤하고 강조합니다 |
| 하이라이트 사이드바 열기 | 오른쪽 사이드바를 엽니다 (리본 아이콘과 같음) |
| 인덱스 다시 만들기 | 코멘트 폴더를 다시 읽습니다 |
| 현재 노트 코멘트 모아 새 노트 만들기 | 문구를 인용으로, 코멘트를 그 아래에 본문 순서대로 적은 노트를 만듭니다 |
| 코멘트 폴더 정리 | "원본 노트별 하위 폴더" 설정에 맞게 코멘트 파일을 다시 놓습니다 |

### 사이드바 검색 문법

| 입력 | 뜻 |
| --- | --- |
| `단어 단어` | 모든 단어가 문구·코멘트·노트 이름 중 어딘가에 있음 (대소문자 무시) |
| `"정확한 구절"` | 구절 그대로 포함 |
| `-단어` | 그 단어가 없는 것만 |
| `#태그` | 코멘트 파일 `tags`에 그 태그가 있음 (`#a`는 `#a/b`도 찾음) |
| `color:이름` | 색 key·색 이름·`#ff8800` 같은 색 값 |
| `note:이름` | 원본 노트 이름에 그 문자열 포함 |
| `is:orphan` / `is:plain` / `is:commented` | 원문 없음 / 코멘트 없음 / 코멘트 있음 |

## 데이터 형식

노트:

```markdown
트랜스포머는 ==셀프 어텐션만으로 시퀀스를 처리한다==%%mn:a1b2c3%% 는 점이 핵심이다.
```

코멘트 파일 (`Annotations/논문정리/논문정리 - 셀프 어텐션만으로 시퀀스를 - a1b2c3.md`):

```markdown
---
mn-id: a1b2c3
mn-source: "[[논문정리]]"
mn-source-path: "연구/논문정리.md"
mn-quote: "셀프 어텐션만으로 시퀀스를 처리한다"
mn-color: yellow
mn-created: 2026-11-24T11:10:00+09:00
mn-updated: 2026-11-24T11:12:30+09:00
tags: []
---
RNN을 빼고도 성능이 나온 이유가 여기서 나온다.
```

- 짝은 파일 이름이나 위치가 아니라 `mn-id`로 찾습니다. 파일 이름을 바꿔도 연결이 유지됩니다.
- 원본 노트 이름을 바꾸거나 옮기면 `mn-source-path`를 플러그인이 고칩니다.
- 앵커 ID는 영문 소문자로 시작합니다. `123456`처럼 숫자로만 된 ID는 YAML이 숫자로 읽기 때문입니다.
- `mn-detached: true`를 넣은 파일은 사이드바에 나오지 않습니다("일반 노트로 남기기").

## 원칙

- 플러그인은 사용자가 요청한 동작에서만 노트 본문을 고칩니다. 열기·스캔·동기화는 본문을 바꾸지 않습니다.
- 파일 삭제는 항상 확인창을 거치고 옵시디언 휴지통으로 보냅니다.
- 네트워크 요청을 하지 않습니다.

### 실제 옵시디언에서 확인해야 할 것

자동 테스트는 가짜 옵시디언 환경에서 돌기 때문에, 아래 항목은 실제 앱에서 직접 확인해야 합니다.

- 라이브 프리뷰에서 옵시디언 자체의 `%%주석%%` 표시와 말풍선 아이콘이 겹치지 않는지 (M6)
- 다크·라이트 테마에서 카드와 하이라이트 글자가 읽히는지 (M10)
- 읽기 모드에서 하이라이트를 누르면 카드가 강조되는지 (M19)
- 하이라이트에 마우스를 올리면 코멘트 미리보기가 뜨는지 (페이지 미리보기 코어 플러그인이 켜져 있어야 함)
- 모바일에서 길게 눌러 메뉴, 카드 아이콘, 입력창 크기
